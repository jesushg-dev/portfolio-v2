# Internationalization

Locales: **en**, **es**, **nl** (`src/i18n/config.ts`). Routing: next-intl plugin + `src/proxy.ts`. Default locale for a **tenant** is `Profile.defaultLocale` (owner seed is `es`).

## Pathnames

Translated public paths live in `pathnames` in `src/i18n/config.ts` (e.g. `/schedule` → `/agendar` / `/plannen`). Internal keys stay English. Analytics normalizes localized paths back with `toAnalyticsPath`.

Admin stays under `/admin/...` (not localized path segments).

## Messages

- UI copy: `messages/en.json` (source of truth), `messages/es.json`, `messages/nl.json`.
- Email copy: `email-templates/messages/{en,es,nl}.json` — see [`email-templates.md`](./email-templates.md).

Unit test `src/lib/i18n/message-key-parity.test.ts` fails CI if a locale is missing keys.

When you add a string:

1. Put it in `en.json`.
2. Translate `es` and `nl` in the same commit.
3. Run `pnpm test` (parity) or the key will break the unit job.

## CMS / seed content

All translatable CMS and domain entities follow a **strict normalized relational architecture**:

1. **Main Entity Table (Language-Agnostic)**:
   - Holds structural and operational data: IDs, user/tenant relation, ordering (`order`), icons (`icon`), numeric/metric values (`value`), URLs, flags (`isVisible`, `featured`), and timestamps.
   - **Never** store localized strings or language-keyed JSON maps (e.g. `{ en: "...", es: "..." }`) directly in the main model.

2. **Dedicated Translation Table (`*Translation`)**:
   - Holds every field that changes per language (e.g. `title`, `description`, `label`, `badge`).
   - Links to the parent entity and to `AppLanguage` via `appLanguageId`.
   - Enforces a unique constraint: `@@unique([<entityId>, appLanguageId])`.
   - Reverse relation is registered on `AppLanguage` (`<Entity>Translation <Entity>Translation[]`).

   **Example:**

   ```prisma
   model SoftSkillsMetric {
     id                          String                        @id @default(auto()) @map("_id") @db.ObjectId
     sectionId                   String                        @db.ObjectId
     section                     SoftSkillsSection             @relation(fields: [sectionId], references: [id], onDelete: Cascade)
     value                       String
     order                       Int                           @default(0)
     SoftSkillsMetricTranslation SoftSkillsMetricTranslation[]
   }

   model SoftSkillsMetricTranslation {
     id            String           @id @default(auto()) @map("_id") @db.ObjectId
     metricId      String           @db.ObjectId
     metric        SoftSkillsMetric @relation(fields: [metricId], references: [id], onDelete: Cascade)
     appLanguageId String           @db.ObjectId
     language      AppLanguage      @relation(fields: [appLanguageId], references: [id])
     label         String

     @@unique([metricId, appLanguageId])
   }
   ```

3. **Seed Data (`prisma/data/*.json`)**:
   - Seed JSON mirrors this by structuring translatable fields as `LocaleMap` objects containing `"en"`, `"es"`, and `"nl"`.
   - Enforced by `localized-completeness.test.ts` and `node scripts/audit-locale-completeness.mjs`.

4. **Public Query Resolution**:
   - Public routers query the main model including `*Translation` rows and resolve strings with `createLocalizedFieldResolver(languages, locale)`:
     ```ts
     const field = createLocalizedFieldResolver(languages, locale);
     const label = field(metric.SoftSkillsMetricTranslation, "label");
     ```

Helpers: `src/lib/i18n/localized.ts`, `localized-display.ts`, `localized-form.ts`.

## Language switcher

`src/components/language-switcher.tsx` switches locale while keeping the equivalent pathname. E2E: `e2e/locale-switching.spec.ts` (projects `public-locale` + smoke).

## Adding a locale

1. Extend `locales` and `pathnames` in `config.ts`.
2. Add `messages/<code>.json` with full key parity.
3. Seed `AppLanguage` + translations in fixtures.
4. Email templates: new folder under `email-templates/messages/` and publish Resend templates.
5. Expand Zod `z.enum(["en","es","nl"])` on CV PDF / process-page routers (they are not inferred from `locales` everywhere yet).
